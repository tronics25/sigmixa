# SigMixa sample workspace

Open this `sample` directory as a VS Code workspace. Each log shows one part of SigMixa:

| Log | Shows |
|---|---|
| `sigmixa-basic.asc` (and `.blf`) | the basic features: decoding (CAN FD, value labels, Scale and Offset), Plugins, time series and the trace |
| `brake-analysis/` `road-test.asc`, `bench-test.asc` | analysis groups: several logs managed as one, and Clips cut from one log |
| `parking-drive/parking-garage.asc` | trajectories in 3D and 2D |

All logs are synthetic and generated by `npm run sample:generate`.

## Basic features — `sigmixa-basic.asc`

- **Decoding.** In **RAW Log**, switch between RAW and Decoded content.
  - `2A0` is a 64-byte CAN FD Frame and `184` a 16-byte one.
  - Scale and Offset give physical values: Coolant Temperature uses Offset −40, Vehicle Speed uses Scale 0.01.
  - `310` and `320` show value labels (gear, doors, drive state); `320` is multiplexed.
  - One `320` Frame at 26.7055 s has only 2 bytes, so the value it should carry cannot be read.
  - Two malformed rows near 12.345 s show parser diagnostics.
- **Time series.** Open **Visualize**.
  - Speed from CAN (km/h) and from `reference-signals.csv` (m/s) are converted onto one speed axis.
  - Signals with different periods (100 ms, 250 ms, the CSV) are joined into continuous lines.
  - Unitless states are drawn with their value labels.
- **Trace.** Below the views, `3C0` is pinned. It is expected every 100 ms, arrives with jitter, stops at 41 s and resumes at 50 s: the interval and deviation columns show it.
- **Plugins.** `sample.property-service` keeps state across Frames: it pairs each `6A0` request with its `6A8` response and labels the result (for example `Set Failure`). Edit each property's name, unit, Scale and Offset in **PLUGINS**. `2A0` also has two simple Plugins, one with a deliberate error.
- **DBC.** Import `sigmixa-basic.dbc` into the workspace's Frame definitions and export it again.

`sigmixa-basic.blf` holds the same supported CAN data. ASC-only malformed rows and remote frames are not in the BLF.

## Analysis groups and Clips — `brake-analysis/`

- The folder is an analysis group. It adds a Pedal to Pressure Ratio to Frame `300` and shares its views with every log it holds.
- `bench-test.asc` and `road-test.asc` were recorded separately; both open with the group's definitions and views.
- `sigmixa-basic.asc` is added to the group from the workspace root. It is listed in both places and uses the definitions of the place it is opened from.
- `road-test.asc` holds three stops in one recording. The Clips **Stop 1**, **Stop 2** and **Stop 3** cut them out. Select them and compare, shifting each in time to line up the brake application. A Clip can also be compared with the bench test file.

## Trajectories — `parking-drive/parking-garage.asc`

A drive up three turns of a car park's helical ramp to the roof, then a right turn into a parking space. Every sensor reports the position of its own mounting point.

- **3D, Drive up the Car Park.** The rear-axle centre and the GNSS antenna. The antenna is 1.5 m higher, and silent under the floors.
- **3D, Four Wheel Tracks.** Each wheel's contact point. Every turn of the ramp draws four rings.
- **2D, Four Wheel Tracks from Above.** The same wheel tracks without height. Open the Clip **Into the Space**: the group's views then show only the turn into the parking space, where the rear right wheel cuts about 0.8 m inside the front right one. The group adds an Inner Wheel Difference lookup from the steering angle, shown below it.
