# SigMixa sample workspace

Open this `sample` directory as a VS Code workspace. Each log shows one part of SigMixa:

| Log | Shows |
|---|---|
| `city-drive/drive.asc` | a three-minute drive to look around first: speed and engine speed, pedals, gear and turn signals, hard braking and the route |
| `basic/sigmixa-basic.asc` (and `.blf`, `.mf4`) | the basic features: decoding (CAN FD, value labels, Scale and Offset), Plugins, time series and the trace |
| `basic/sigmixa-basic-decoded.csv` (and `.mdf`) | a log of values converted from CAN data (speed and temperature), to view next to a CAN log on the comparison screen |
| `brake-analysis/` `road-test.asc`, `bench-test.asc` | analysis groups: several logs managed as one, and Clips cut from one log |
| `parking-drive/parking-garage.asc` | trajectories in 3D and 2D |

Each folder is an analysis group. Its logs open with the views the group shares, except the CAN logs in `basic/`, which open with their own views. Switch the view settings between **This file** and **Shared in group** to see the other ones.

All logs are synthetic and generated by `npm run sample:generate`.

## City drive — `city-drive/drive.asc`

A drive from a parked start through city streets, with two stops at lights and a left and a right turn, onto a highway to 100 km/h, where a car cuts in ahead, then hard braking behind that car, and a stop.

- The folder is an analysis group. Its views follow the drive, and each graph has a state timeline under it: speed and engine speed with the road and the gear (the engine speed drops at each upshift), the pedals with the drive mode, the steering and front wheel speed difference with the turn signals, the car ahead with the collision warning, and the brake pressure and front wheel speeds with the brake phase (ABS pulses the front wheels). Then the route from above and the driving profile.
- **Frame timing** and **Receive interval** check the data: the motion sensor `1A1` drops out for 0.7 s on the highway.
- The Clips **Highway Merge** and **Hard Braking** cut out the two highlights.
- The group adds Frame `2B0` (the drive states) and Frame `1D0` (the position on the route).

## Basic features — `basic/sigmixa-basic.asc`

The folder is an analysis group. Its logs share graphs of the speed and coolant temperature that every log in it records.

- **Decoding.** In **RAW Log**, switch between RAW and Decoded content.
  - `2A0` is a 64-byte CAN FD Frame and `184` a 16-byte one.
  - Scale and Offset give physical values: Coolant Temperature uses Offset −40, Vehicle Speed uses Scale 0.01.
  - `310` and `320` show value labels (gear, doors, drive state); `320` is multiplexed.
  - One `320` Frame at 26.7055 s has only 2 bytes, so the value it should carry cannot be read.
  - Two malformed rows near 12.345 s show parser diagnostics.
- **Time series.** Open **Visualize**.
  - Signals with different periods (100 ms, 250 ms) are joined into continuous lines.
  - Unitless states are drawn with their value labels.
- **Trace.** Below the views, `3C0` is pinned. It is expected every 100 ms, arrives with jitter, stops at 41 s and resumes at 50 s: the interval and deviation columns show it, and so do the **Frame timing** and **Receive interval** views.
- **Plugins.** `sample.property-service` keeps state across Frames: it pairs each `6A0` request with its `6A8` response and labels the result (for example `Set Failure`). Edit each property's name, unit, Scale and Offset in **PLUGINS**. `2A0` also has two simple Plugins, one with a deliberate error.
- **DBC.** Import `sigmixa-basic.dbc` into the workspace's Frame definitions and export it again.

`sigmixa-basic-decoded.csv` is a CSV log of the vehicle speed (m/s) and coolant temperature decoded from frame 0x2A0 of `sigmixa-basic.asc`.

`sigmixa-basic.blf` holds the same supported CAN data. ASC-only malformed rows and remote frames are not in the BLF.

`sigmixa-basic.mf4` holds the same CAN data as ASAM MDF 4 bus logging, remote frames included, and starts at the ASC log's date. Only the malformed rows are left out. It also stores the values of `sigmixa-basic-decoded.csv` as measured signals: in **Visualize**, they are under **MF4 · Reference**, next to the same values from the CSV. **MF4 · Chassis** holds an array (`WheelSpeed`, four wheels) and a structure (`Position` with X and Y), listed under their names.

`sigmixa-basic-decoded.mdf` is an MDF 3 log of the same decoded values as `sigmixa-basic-decoded.csv`.

## Analysis groups and Clips — `brake-analysis/`

- The folder is an analysis group. It adds a Pedal to Pressure Ratio to Frame `300` and shares its views with every log it holds.
- `bench-test.asc` and `road-test.asc` were recorded separately; both open with the group's definitions and views.
- `basic/sigmixa-basic.asc` is added to the group from the basic group. It is listed in both places and uses the definitions of the place it is opened from.
- `road-test.asc` holds three stops in one recording. The Clips **Stop 1**, **Stop 2** and **Stop 3** cut them out. Select them and compare, shifting each in time to line up the brake application. A Clip can also be compared with the bench test file.

## Trajectories — `parking-drive/parking-garage.asc`

A drive up three turns of a car park's helical ramp to the roof, then a right turn into a parking space. Every sensor reports the position of its own mounting point.

- **3D, Drive up the Car Park.** The rear-axle centre and the GNSS antenna. The antenna is 1.5 m higher, and silent under the floors.
- **3D, Four Wheel Tracks.** Each wheel's contact point. Every turn of the ramp draws four rings.
- **2D, Four Wheel Tracks from Above.** The same wheel tracks without height. Open the Clip **Into the Space**: the group's views then show only the turn into the parking space, where the rear right wheel cuts about 0.8 m inside the front right one. The group adds an Inner Wheel Difference lookup from the steering angle, shown below it.
